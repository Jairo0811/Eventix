# Eventix v1.3.0 — Commerce & Organizer Experience

## Estado

Release estable de la línea v1.3.0. La integración de una pasarela de pago real continúa reservada para v1.4.0.

## Cambios principales

### Customer Experience
- consulta de boletas digitales y detalle;
- acceso a QR, PDF, Google Wallet y Apple Wallet;
- historial y experiencia post-compra sobre el modelo comercial existente.

### Commerce Core
- ventas, pagos y refunds sin duplicar agregados de dominio;
- reembolsos totales y parciales por boleta;
- estado `PARTIALLY_REFUNDED` y contabilidad acumulada `refunded_amount`;
- invalidación selectiva de boletas reembolsadas;
- bloqueo pesimista para evitar doble refund concurrente;
- comisión Eventix y neto del organizador recalculados sobre el importe retenido;
- ledger de liquidaciones basado en cada `PaymentTransaction REFUND` aprobado;
- idempotencia de refunds liquidados mediante `payment_transaction_id`.

### Eligibility & Benefits
- instituciones, promociones y miembros autorizados;
- verificación institucional con HMAC-SHA256 para identificadores sensibles;
- modos `PUBLIC`, `PRIVATE` y `CONTROLLED_ACCESS`;
- grupos genéricos: promoción, alumni, familiares, staff, VIP y custom;
- relaciones familiares verificadas con aprobación/rechazo/revocación;
- límites configurables de familiares;
- beneficios configurables por grupo;
- descuentos porcentuales/fijos/entrada gratuita aplicados server-side;
- límites de compra y tipos de entrada exclusivos aplicados server-side;
- compatibilidad explícita con cupones sin stacking monetario implícito;
- auditoría de verificaciones y decisiones.

`EARLY_ACCESS`, `RESERVED_INVENTORY` y `PRIORITY_ACCESS` permanecen como capacidades configurables del modelo, pero una ventana general de venta, una reserva transaccional dedicada y una cola de prioridad requieren infraestructura adicional. No se presentan como comportamiento operativo completo en esta release.

### Organizer Experience
- dashboard comercial con ventas brutas, descuentos, refunds, comisión y neto;
- métricas de boletas activas/usadas y ocupación;
- liquidaciones persistentes con trazabilidad por movimiento financiero;
- administración de grupos, miembros, relaciones y beneficios.

### Engagement
- centro de notificaciones internas persistente;
- estados leído/no leído;
- navegación dedicada;
- eventos internos de compra y reembolso;
- notificaciones por correo existentes se mantienen como canal independiente.

### Seguridad y QA
- Spring Security y RBAC por dominio;
- ownership para organizadores;
- Flyway incremental para SQL Server 2022;
- Testcontainers;
- protección de operaciones financieras mediante locks pesimistas;
- GitHub Actions con Maven verify, Docker Compose, readiness, security headers, persistencia, rotación de credenciales, Trivy y SBOM.

## Migraciones v1.3.0

## Compatibilidad

- Java 21
- Spring Boot 3.5.x
- Thymeleaf / Bootstrap 5
- Microsoft SQL Server 2022
- Flyway
- Docker / Docker Compose

## Próxima línea

v1.4.0 queda reservada para integración de pagos real y para capacidades que necesitan infraestructura propia, como ventanas avanzadas de venta, inventario reservado transaccional y prioridad/colas de acceso.
